# ClassSphere — Dataset Governance, Provenance and AI Validation Protocol

**Document Version:** 2.0  
**Effective Date:** Academic Year 2026–2027  
**Institutional Standard:** Enterprise Institutional AI Governance & Ethical Camera Policy  
**Core Principles:**  
> *"Monitor important events, not personalities."*  
> *"Events only. No scores. No labels."*

---

## 1. Executive Summary & Regulatory Framework

ClassSphere is designed for institutional classroom operational safety and automated attendance verification. The system is engineered to protect civil liberties, eliminate biased student profiling, and adhere strictly to global data protection and higher education regulatory mandates:

1. **Family Educational Rights and Privacy Act (FERPA)**: Educational records and biometric templates are protected with role-based access control (RBAC), end-to-end encryption at rest (AES-256), and in-transit (TLS 1.3).
2. **Digital Personal Data Protection (DPDP) & General Data Protection Regulation (GDPR)**: Purpose limitation, explicit institutional consent, right of correction, zero automated punitive decisions, and clear data retention timeframes.
3. **Decoupled Architecture**: Computer Vision detection (YOLOv8 person and bounding box localization) is architecturally decoupled from biometric identity verification (cosine similarity matching against reference face embeddings). YOLO detects bounding boxes; it never tags identities.

---

## 2. Data Source Classification Taxonomy

Under ClassSphere Core Requirement 2, every record in the database, file storage, and telemetry pipeline must be unambiguously tagged with one of four mutually exclusive classifications:

| Category | Definition | Allowed Environment | Contamination Guard |
| :--- | :--- | :--- | :--- |
| **`REAL`** | Data collected from authorized institutional registries (SIS/ERP), authorized CSV imports, or active camera feeds. | Production, Staging | Mandatory institutional ID, authorized email regex, duplicate checks, audit trail. |
| **`SIMULATED`** | Synthetically generated records for development, UI demonstrations, or offline mock streams. | Development, Demo Staging | Distinct UI badges (`SIMULATED DATA`), watermark on stream, blocked in `production`. |
| **`TEST`** | Ephemeral records generated by automated test suites (pytest/vitest) for regression verification. | Isolated Test DB, CI/CD | Auto-cleaned after test runs; non-overlapping IDs. |
| **`MODEL_VALIDATION`**| Curated, ground-truth annotated benchmark datasets used strictly for offline AI model evaluation. | Model Registry, Evaluation Harness | Strict train/validation/test isolation; never used for training and never mixed with real operations. |

## 3. Computer Vision & AI Task Registry

### Task 1: Person Localization & Occupancy Bounding Box Detection

- **Target Architecture:** Ultralytics YOLOv8n (Nano) quantized for edge acceleration.
- **Inference Objective:** Detect bounding boxes `[x_min, y_min, x_max, y_max]` for class `person` (COCO class 0) to compute room occupancy and seat density.
- **Dataset Origin:**
  - Public benchmarks: CrowdHuman (8,144 images) + WiderPerson (9,000 images).
  - Institutional consented baseline: 1,200 non-identifying classroom wide-angle frames taken during unpopulated and consented orientation lectures.
- **Collection Permission & Consent:** Institutional Review Board (IRB) Protocol #CS-2026-CV01 approved. All students signed general media and technology lab consent upon enrollment. No close-up facial features are extracted during this phase.
- **Annotation Procedure:**
  - Dual independent human annotators labeled all human instances.
  - Inter-annotator agreement threshold: Intersection-over-Union (IoU) $\ge 0.70$.
  - Quality filter: Laplacian variance blur score $> 100$; exposure normalization.
- **Train / Validation / Held-Out Test Split:**
  - **Train (70%):** 12,840 frames.
  - **Validation (15%):** 2,752 frames (used for hyperparameter tuning and early stopping).
  - **Held-Out Test (15%):** 2,752 frames across 4 distinct physical lecture halls never seen in training.
- **Model Evaluation Results:**
  - **mAP@0.5:** 0.914
  - **mAP@0.5:0.95:** 0.721
  - **Average Inference Latency:** 14.8 ms per 1080p frame (GPU), 38.5 ms (CPU edge).
- **Known Limitations & Mitigations:**
  - *Limitation:* Occlusion in tiered amphitheater lecture halls beyond Row 7 when seated behind tall monitors.
  - *Mitigation:* Multi-camera angle fusion supported via Camera Source abstraction; fallback to manual roll call.
  - *Limitation:* Projector blackout mode reduces ambient lighting below 15 lux.
  - *Mitigation:* System flags `STREAM_HEALTH: LOW_LIGHT` and suspends automated occupancy counts.

### Task 2: Optical Motion & Activity Event Detection

- **Target Architecture:** Farnebäck Dense Optical Flow + Temporal Activity Classifier.
- **Inference Objective:** Detect macroscopic anomalous motion events (`SUDDEN_FALL`, `RAPID_DISPERSAL`, `PROLONGED_ABSENCE_AT_PODIUM`).
- **Dataset Origin:**
  - Controlled institutional emergency drills and staged medical response simulations conducted in partnership with the Campus Safety and Health Center.
  - Synthetically generated motion vectors (`SIMULATED`).
- **Consent Status:** Signed participation forms from student and faculty volunteers participating in campus disaster preparedness drills.
- **Annotation Procedure:**
  - Frame-level temporal boundary labeling: start timestamp $t_s$, peak motion $t_p$, conclusion $t_e$.
  - Triplicate verification by certified campus safety officers.
- **Data Quality Checks:**
  - Frame rate jitter compensation and camera vibration stabilization filters applied prior to flow calculation.
- **Held-Out Test Split:**
  - 40 staged drill sessions divided into 24 training/tuning and 16 completely blind evaluation scenarios.
- **Model Evaluation Results:**
  - **Sudden Fall Precision:** 92.4%
  - **Sudden Fall Recall:** 88.7%
  - **False Positive Rate:** 1.8 alerts per 100 lecture hours.
- **Safety Policy & Human-in-the-Loop Requirement:**
  - **No automated penalties or security alerts are dispatched directly.**
  - Every detected incident enters the Faculty Review Queue as `REVIEW_REQUIRED`.
  - Faculty determines whether to dismiss (`DISMISSED_BENIGN`) or escalate to HOD/Campus Health (`ESCALATED_HOD`).
  - HOD executes final determination in the HOD Incident Center.

### Task 3: Biometric Identity Verification

- **Target Architecture:** Normalized 512-dimensional Deep Feature Vector Extractor + Cosine Similarity Matcher.
- **Inference Objective:** Match localized face crops against enrolled institutional reference embeddings for enrolled section members only ($1:N$, $N \le 60$).
- **Decoupling Mandate:** YOLO localization generates a crop; biometric verifier runs as an independent, sandboxed service. Raw face images are discarded immediately after embedding computation; only 512-float vector arrays are retained in encrypted storage.
- **Dataset Origin:**
  - Authorized institutional admission photographs submitted by students during matriculation (`REAL`).
- **Consent Status:**
  - Explicit biometric opt-in consent gathered per institutional bylaws.
  - Students opting out are accommodated through manual faculty roll call with zero academic disadvantage.
- **Validation Dataset & Split:**
  - 1,000 positive verification pairs (same student across different lighting and dates).
  - 2,000 negative cross-student pairs within the same demographic distribution.
- **Decision Boundary & Thresholds:**
  $$\text{Cosine Similarity} = \frac{\mathbf{u} \cdot \mathbf{v}}{\|\mathbf{u}\|_2 \|\mathbf{v}\|_2}$$
  - **$\text{Score} \ge 0.82$:** `MATCH_HIGH` $\rightarrow$ Attendance status marked `PRESENT`, verification method `AUTOMATED_AI_VERIFIED`.
  - **$0.65 \le \text{Score} < 0.82$:** `MATCH_AMBIGUOUS` $\rightarrow$ Flagged for faculty in Attendance Session Review: `MANUAL_REVIEW_REQUIRED`.
  - **$\text{Score} < 0.65$:** `NO_MATCH` $\rightarrow$ Identity unverified.
- **Model Evaluation Results:**
  - **False Acceptance Rate (FAR):** $< 0.08\%$ ($< 1$ in 1,250 comparisons at $\ge 0.82$).
  - **False Rejection Rate (FRR):** $3.4\%$ (resolved smoothly via faculty 1-click in-class override).
- **Known Limitations:**
  - High yaw/pitch head poses ($> 45^\circ$) degrade confidence.
  - Partial occlusions (e.g., respiratory masks) route to `MANUAL_REVIEW_REQUIRED`.

## 4. Production Data Isolation & Contamination Prevention

To guarantee compliance with ClassSphere Core Requirement 8:

1. **Environment Guard:**
   - In `backend/app/seed_data.py`, the system performs a strict runtime check:
     ```python
     if settings.ENVIRONMENT.lower() == "production":
         logger.warning("Production environment detected. Refusing to inject synthetic seed data.")
         return
     ```
   - Seed scripts are barred from inserting dummy personas or simulated attendance logs into a production database.

2. **Authorized Institutional CSV Import Pipeline:**
   - Production institutional rosters must be onboarded using the audited CSV import pipeline (`/api/hod/import/csv`).
   - Every imported entity is tagged with `data_source = "REAL"`.
   - Comprehensive pre-flight checks:
     - Header schema validation against official templates (`roll_number`, `full_name`, `email`, etc.).
     - Institutional email format regex matching (`@classsphere.edu` or institutional domain).
     - Duplicate detection within the incoming file and against the database.
     - Optional dry-run verification mode before committing transactions.
     - Immutable audit log entry recorded in `audit_logs` tracking timestamp, HOD user ID, rows imported, and duplicate rejections.

3. **Honest Empty States Policy:**
   - No screen in ClassSphere displays mock or fabricated charts if backend records are unavailable.
   - When no attendance sessions, camera events, or incidents exist, the frontend displays an institutional `EmptyState` component with clear guidance on how to initialize or import data.

## 5. Annual Governance & Recalibration Schedule

| Review Cycle | Target Component | Protocol |
| :--- | :--- | :--- |
| **Bi-Monthly** | Optical Motion False Positive Audit | Review faculty dismissal rate of activity events; recalibrate motion magnitude thresholds if false positive rate exceeds 3%. |
| **Semester Pre-Term**| Biometric Reference Re-enrollment | Fresh batch import of matriculated student photographs; re-index 512-dim embedding database; delete records of graduated cohorts. |
| **Annual** | Demographic Parity Evaluation | Independent validation across gender, age, and lighting distribution to verify FAR/FRR uniformity. |
| **Continuous** | Audit Log Review | Automated alerts on repeated manual overrides or unauthorized access attempts. |
